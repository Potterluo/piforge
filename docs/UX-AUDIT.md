## §1 十条最痛的问题

### 1. 侧边栏是"项目列表"，会话被挤到 1301px 以下——日常用户每天第一件事就卡住

**现象.** 登录 `dev@` 打开首页，侧边栏从上到下是：35 个项目行（其中多行因为名字长折成两行）、然后才是「会话」组。实测：「会话」组的标题在 `y=1301`，视口高 900；侧边栏内容区 `scrollHeight=1241 / clientHeight=620`。也就是说**不滚动根本看不到任何会话**，滚动到底又看不到项目列表顶部（`05-sidebar-scrolled-to-sessions.png`，操作：登录 → 首页 → 把侧边栏内容滚到底）。点进项目后才出现会话，且「会话」组仍在 35 个项目之后（`03-dev-session.png`）。首页没有任何"继续上次"的入口，35 张项目卡片里也没有"哪个项目有会话在跑"（`01-dev-home.png`）。

**为什么会痛.** 用户每天打开产品想的是"接着干昨天的活"，产品回答的是"选一个仓库"。要回到昨天的会话，他得先想起它在哪个项目、在 35 行里找到那个项目、点进去、再在会话列表里找到那条——而这四步里每一步都可能找错。命令面板救不了：`Ctrl+K` 里 44 个条目中 35 条是项目、0 条是会话；输入会话标题「qa14 首轮」→ `没有匹配的命令`（`07-command-palette.png`、`08-palette-search-session-title.png`，操作：`Ctrl+K` → 输入"qa14 首轮"）。产品里**没有任何会话搜索**。

**最小改法.** 把侧边栏的「项目」组整块删掉（项目已经在首页和左上角），「会话」组升到顶部并改成跨项目的最近会话：`GET /v1/sessions` 不带 `project` 时本来就返回该用户全部会话（实测 43 条），不需要新接口。分组顺序固定为 `运行中 → 需要你（失败/等你确认）→ 今天 → 更早`，每行标题 + 项目名小字。顶部 `PiForge / 所有项目 ⌄` 改成真的项目切换菜单（现在它只是个指向 `/` 的链接，见 §2.2）。搜索框接 `GET /v1/sessions?q=`（后端已支持，客户端 `sessions.list` 需要把 q 透传出去，见 `docs/STATUS.md` FR-1.5）。

**影响面.** 每个日常用户的每一次会话切换；也是新用户第一次觉得"这东西有记忆"的地方。

**代价.** M（侧边栏重排 + 会话列表改为全局 + 搜索接线；约 2–3 天，其中一半是状态分组）。

### 2. 新账号的第一条消息 100% 失败，而错误指向一个他在界面上根本看不到的 provider

**现象.** 管理员建号 → 新用户登录 → 建项目（`hello-world`，仓库 `https://github.com/octocat/Hello-World.git`）→ 建会话 → 输入第一句话按 Enter。结果：**等了 91 秒仍没有任何回复（我们在这里放弃等待），没有红色错误块，输入框里的字还在**，只有右下角一个几秒后消失的 toast：「发送失败 / 服务商「volc」尚未配置，请到「设置 → 模型与凭据」添加」（`62-firstrun-send-failure-toast.png`、`29-firstrun-first-reply.png`；操作步骤见 §4）。会话头部同时写着 `跟随默认（unknown）`（同图）。服务端日志与 API 都确认：`400 no_model: the provider "volc" is not configured`。而在这个新账号的「模型与凭据」页里只有 `shared-anthropic` 一个继承项（`缺少 key`），**没有 volc**——错误里点名的东西用户看不到、也修不了（`63-newuser-providers.png`；API `GET /v1/providers` 同账号只返回这一条）。页面上也没有"这个账号的默认模型是谁 / 能不能用"这一行。

**为什么会痛.** 这是首小时里唯一必须成功的一步，它失败了；失败信息指向一个空页面；错误是瞬态的，用户回头看不到发生过什么；输入框没清空更像"没按下去"。用户此时会做的三件事（再按一次 Enter、刷新、去设置页找 volc）全都不会解决问题，因为真正的修法在管理员那边（继承的 provider 没 key、部署默认 `PIFORGE_DEFAULT_PROVIDER=volc` 对普通用户不可见）。

**最小改法.** 三层，都不需要新后端能力：① 头部把 `unknown` 变成明确结论——解析不到就写「这个账号还没有可用模型」，不要打印 `unknown`；② 发送失败不要 toast，改成 composer 上方常驻错误条：`这个账号还没有可用的模型 · 去「模型与凭据」`（错误码 `no_model` 里已经带了 provider 名，前端 `errors.ts` 已有映射，直接复用）；③ 管理员侧：`/admin/status` 的 provider 卡片上标出「共享但缺 key」（列表接口已返回 `has_key`），让配置问题在管理员那里显形，而不是由新用户撞出来。

**影响面.** 每一个新入职的人；也是管理员唯一会收到"这东西不能用"投诉的地方。

**代价.** S（前端 1 天；管理员提示半天）。

### 3. 一次运行被切成 7 个"PiForge"——回复越长，噪音越多

**现象.** 一次提问（"先运行 ls 看看目录，再用一句话说明这个仓库是做什么的"）产生 3 轮工具调用。转录区里出现 **7 个 assistant turn、7 次「PiForge」、4 个模型徽章、8 个时间戳（全部是 `19:59`）**，同一段答案被若干「思考」折叠行和 3 行「1 个工具调用 执行命令 11ms」切成碎片（`34-run-settled.png`；操作：登录 dev → 项目 `qa14-core` → 会话 `UX 审计 · 工具调用`）。每个 assistant turn 的 header 都是「PiForge deepseek-v4-flash」，因为渲染单位是 Pi 的 entry 段，不是"这次运行"（`components/session/message-item.tsx` 的 `MessageHeader`）。用户的提问气泡下、每个工具组前、每段中间叙述前，都重复一次。

**为什么会痛.** 转录区是产品的主界面。作者标签重复 N 次不提供任何信息（一个人只有一个 agent，模型在一次会话里也不变）；时间戳精确到分钟、同一分钟内出现 8 次，等于没有；真正需要一眼看到的"这是最终答案 / 这是过程"反而没有区分。结果是：一段答案看起来像七个不同的人各说了一句。

**最小改法.** 三处小改动：① `MessageItem` 的 header 只在**角色切换**时渲染（同一 run 内连续的 assistant turn 共用第一个 header）；② 模型徽章从每轮移到会话 header 那一行（那里已经有了 `跟随默认（deepseek-v4-flash）`），turn 内不再显示；③ 时间戳只在 hover/footer 显示（现在已经是 hover 才显示，但 footer 里的 `formatClock` 在截图中仍然逐个出现，改成每个 run 一次）。顺带把「思考」「1 个工具调用」的行高压缩到一行。

**影响面.** 每一次对话，每一位用户。

**代价.** S（0.5–1 天，纯前端）。

### 4. 按 Esc 停止，界面告诉你"模型调用失败，去检查密钥"

**现象.** 一个长 run 进行中按 Esc 停止 → 转录区出现红色错误块：「模型调用失败 / Request was aborted / 检查「设置 → 模型」里这个 provider 的地址与密钥，然后重新发送。」（`36-run-after-escape.png`、`35-run-long-running.png`；操作：会话页 → 输入长文请求 → Enter → 1.2 秒后按 Esc）。同时底部 toast 是「已中断，排队消息已回填」——同一个动作，两套说法。红色块里的 "Request was aborted" 是原始英文。

**为什么会痛.** 用户做的是"停"，产品回答的是"坏了"。红块会让人以为自己的操作损坏了什么，并且把人引向一个不存在于侧边栏的菜单名（页面叫「模型与凭据」，见 `13-settings-general.png` 的设置导航）。更糟的是：`Request was aborted` 是 Pi 的内部文案，出现在最显眼的位置。后端其实已经区分了这件事——`contracts.EvRunAborted`、`run.settled{aborted:true}`，前端 `reduce.ts` 里也有 `state.aborted`——所以这是**渲染层没有用它**，不是能力缺失。

**最小改法.** `run.aborted` 时把最后一个 assistant turn 的 `turn.error` 丢掉，改渲染一行中性状态：「已停止 · 19:59」（灰色，不占红色）。`MessageItem` 里对 `turn.error` 的判断加一个 `aborted` 分支即可。

**影响面.** 所有用过停止键的人；也是"这产品可不可信"的关键一击。

**代价.** S（0.5 天）。

### 5. 右侧检查器默认吃掉 56% 宽度，其中一半是"未打开文件"

**现象.** 打开任何会话，右栏默认 56%（`03-dev-session.png` 里 662px/1440px），内容是文件树 + 一块「未打开文件 / 从左侧文件树选择一个文件即可预览。」；用户什么都没选，这块空白就一直是屏幕最大的一块。左栏对话只有 44%，一段 300 字回答要折成很窄的一条（`03-dev-session.png`）。窄屏更糟：390px 宽时右栏仍是 218px（56%），composer 只剩 145px 宽，header 左侧的会话标题/副标题在视觉上消失，右侧的 `Sidecar` 被切掉（`41-mobile-session.png`；操作：390×844 视口 → 登录 → 直接打开会话 URL）。

**为什么会痛.** 这个页面几乎所有时间都在读对话，产品把 56% 的屏幕给了"还没打开的文件"。它同时在窄屏上把主界面压到不可读——不是"移动端体验差"，是**在手机上没法读对话**。

**最小改法.** 默认比例改成 68/32，且右栏默认折叠到图标栏（代码里已有 `collapsedSize="44px"` 和 rail，见 `workbench.tsx`）；`< md` 时右栏默认完全隐藏，从 header 的图标打开成 Sheet。删除"未打开文件"空态里那句长说明，改成一行「选择一个文件查看」。

**影响面.** 所有会话页；手机/窄窗口用户是致命的。

**代价.** S（1 天，主要是窄屏断点和默认值）。

### 6. 项目名必须在创建时凭空想出，而且创建后永远改不了

**现象.** 「新建项目」对话框三个字段：名称（必填，`autoFocus`）、仓库地址、基准分支。仓库地址已经填了 `https://github.com/octocat/Spoon-Knife.git`，名称空着点「创建」→ 浏览器原生气泡「请填写此字段。」（`50-project-name-required.png`；操作：首页 → 新建项目 → 填仓库地址 → 点创建）。名字不能从仓库派生，也不能事后改：项目页 header 只有 `main / 沙箱 / N 个会话 / 新会话`，没有 kebab；全站唯一的项目删除入口藏在"没有 worktree"的会话里（`48-broken-session.png`）。而 `PATCH /v1/projects` 是支持改名的（`project_handlers.go` 的 `handlePatchProject` 收 `name`），只是界面没有入口。

**为什么会痛.** 用户被迫为一个"仓库"再取一次名字，取完发现取错了也改不了——最后只能新建一个项目重来。仓库地址本身已经是一个全局唯一的、机器可读的名字；再要一个人名，是把系统的索引负担转给用户。

**最小改法.** ① 名称字段改为非必填，输入仓库地址时实时把 basename 填进去（`Spoon-Knife.git` → `Spoon-Knife`），用户可改；留空且无仓库时用「空白工作区 · 10-29 20:03」。② 项目页 header 加 kebab：重命名（调已有 PATCH）、删除（调已有 DELETE，二次确认写清"会话会一起消失"）。

**影响面.** 每个新项目；每个起错名字的人。

**代价.** S（1 天）。

### 7. 首页回答不了"现在有什么在跑 / 什么需要我"

**现象.** 一个 run 正在进行时切到项目页：会话行写着「主会话 · 运行中 · 刚刚」（`32-running-project-page.png`）。切到首页：35 张卡片，全部只有 `main / 沙箱 · 已就绪|已暂停|未创建 / N 个会话 / 相对时间`，**没有任何运行中标记**（`33-running-home.png`；操作：发消息 → 1.5 秒后点侧边栏项目 → 再点「所有项目」回首页）。侧边栏里的运行标记是一个 6px 的圆点（`StatusDot` 的 `size-1.5`），在 35 行里基本看不见。产品唯一的"通知"面板只收管理员只读查看的记录，文案自己写着"这里没有别的通知类型——它不是消息中心"（`45-notifications.png`；操作：侧边栏 → 通知）。

**为什么会痛.** 编码 agent 是异步的：用户发完就切走，过一会儿回来第一句话是"跑完没有"。现在这个问题的答案需要他逐个打开项目去找。沙箱状态（`已暂停`）反而占据了卡片上最显眼的位置，一屏里几乎每张卡都写着"已暂停"——这是资源层的内部状态，不是用户的事。

**最小改法.** ① 首页每张项目卡片把「沙箱 · 已暂停」换成「1 个运行中 / 1 个失败」，没有就显示"最后活动 2 分钟前"；② 侧边栏会话行在标题前加文字徽章而不是圆点（`运行中` / `失败`）；③ run 结束时用现成的 toast（SSE `run.settled` 已在）提示「『会话名』跑完了」，并在离开的页面上更新计数。全部前端，数据都在 `sessions.list` 的 `status` 里。

**影响面.** 每天几十次的"回来看看"；多项目并行的用户是刚需。

**代价.** S（1 天）。

### 8. 错误面：原始英文 JSON、过期的菜单名、瞬态 toast

**现象.** 三个实例。① 模型不存在时，红色块里直接贴了 provider 的原始响应：`404: {"message":"The requested model does not exist. Please check the 'model' parameter in your request, or call GET /v1/models to list available models.",...}`，下面还建议去「设置 → 模型」（`49-bad-model-session.png`）。② 停止被当成失败（§1-4，`36-run-after-escape.png`）。③ 首次发送失败只有 toast，且输入框内容保留、没有任何常驻状态（`62-firstrun-send-failure-toast.png`）。同类问题还有 `header` 里的 `跟随默认（unknown）`（同图）、转录底部的 `Scroll to end`、分支面板的 `Close`、菜单里的「克隆（再试一次）」（`09-session-actions-menu.png`）。

**为什么会痛.** 错误是用户最需要被准确告知的时刻。现在这一屏同时出现三种语言（中文标题、英文原始体、英文按钮）和两个不存在的菜单名（「设置 → 模型」），还夹着内部术语（`provider`、`model` 参数、`GET /v1/models`）。用户能做的只有截图发给管理员。

**最小改法.** ① `message-item.tsx` 里那句「检查「设置 → 模型」里这个 provider 的地址与密钥」改成「检查「模型与凭据」里这个模型服务的地址与密钥」并做成链接；② 原始响应折进"详情"，默认只显示一行人话（`errors.ts` 已经能翻译，只是这里没走它）；③ 把 `Scroll to end` / `Close` 换成中文；④ `克隆（再试一次）` 改「复制一份」。

**影响面.** 所有失败路径；也是支持成本的主要来源。

**代价.** S（1 天）。

### 9. 管理台只有数字，没有下钻；共享配置坏了也没人知道

**现象.** `/admin/status` 四张卡：活跃用户 4/4、运行中的 agent 16、沙箱 1/27、会话 43，"事件记录共 3,490 条"（`20-admin-status.png`）；每张卡都没有链接或按钮，看不到"是哪些"。`/admin/support`（只读排障）要求管理员**手填会话 id**：「会话 id 由用户提供」（`60-admin-support-form.png`）。`/settings/providers` 里管理员共享的 `shared-anthropic` 显示「缺少 key」，但它下面出现在"继承"列表里、没有任何"去补 key"的动作（`22-admin-providers.png`）。

**为什么会痛.** 管理员能看到的都是"多少"，看不到"谁/哪个"，所以 16 个运行中的 agent 既不能确认也不能处理；用户报障时管理员要不到会话 id（用户界面上会话 id 根本不显示）；共享 provider 缺 key 这件事只在普通用户的发送失败里显形——排障方向是反的。

**最小改法.** ① `运行中/失败` 两个数字变成可点，跳到一个只有 id、项目名、最后活动、状态的管理员列表（管理员本来就看不到内容，不越权）；② 只读排障的输入框旁加"从最近 7 天的会话里选"下拉（管理员可见元数据，不含内容）；③ 共享 provider 卡片上的「缺少 key」变成行动项，链到编辑。

**影响面.** 管理员每天；也决定了普通用户撞到配置问题后多久能恢复。

**代价.** M（列表接口要有管理员维度的元数据；如果不想加接口，至少做 ③，S）。

### 10. 键盘：Tab 要穿过 35 个项目链接才到输入框；菜单只在 hover 出现

**现象.** 会话页从页面顶部按 Tab，前 26 个焦点依次是：收起侧边栏 → 搜索命令 → 项目切换 → 新建项目 → 22 个项目链接……（`43-keyboard-focus.png`；操作：会话页 → 连按 Tab 26 次并记录 `document.activeElement`）。会话操作菜单（重命名/归档/导出/对比/克隆/删除）的触发器是 `showOnHover`，键盘聚焦不到，只能鼠标 hover（`09-session-actions-menu.png`）。另外 `Ctrl+B` 折叠后，左侧只剩一条游离的项目行叠在对话上（`44-collapsed-rail.png`）——这块正是另一个 agent 在改的区域，我只记录现象。

**为什么会痛.** 每天用键盘的人（也就是最重度的那批）每进一个会话都要先穿过整个项目列表；而他要找的会话操作，恰恰是唯一必须用鼠标的部分。这不是无障碍合规问题，是重度用户的肌肉记忆被反复打断。

**最小改法.** ① 主内容区加 skip link（`跳到对话`），Tab 一次直达 composer；② 会话列表从 DOM 顺序上放到项目之前（与 §1-1 同一改动）；③ `SessionActions` 的 kebab 改为 `focus-visible` 可见 + `Shift+F10`/右键打开；④ 折叠态的问题交给正在改那块的人，别在这里重复修。

**影响面.** 键盘用户、每天几十次切换的人。

**代价.** S（skip link + 菜单可达性 1 天；折叠态另算）。

## §2 针对 owner 提的四点

### 2.1 "为什么必须给项目和会话起名字？"——不是必须；项目名要派生，会话名的输入框该删掉

**判断：会话这一半已经做对了，项目这一半没做，而且做错的方式比"多问一个字段"更糟——它不可撤销。**

会话：新建对话框里写着「留空则用第一条消息自动命名」，后端 `autoTitle` 取首行 40 字（`message_handlers.go`，单测 `TestFirstMessageNamesAnUntitledSession`）。也就是说**会话根本不需要那个输入框**，它只是被放在最上面、还 `autoFocus` 抢焦点（`06-new-session-dialog.png`）。（本次审计里那条新会话因为发送失败，没能观察到自动命名生效，这是 §1-2 的后果，不是命名逻辑的问题。）项目：名称必填、不能派生、不能改（§1-6，`50-project-name-required.png`）。

界面上所有要求命名的位置（全量）：

| 位置 | 是否必填 | 能否改 | 应该怎么办 |
|---|---|---|---|
| 新建项目 · 名称 | 是（原生 `required`） | 否 | 改为非必填，从仓库 basename 派生；加项目重命名 |
| 新会话 · 标题 | 否 | 能（kebab） | 从对话框里删掉，只留「开始」 |
| 会话重命名 | — | — | 保留（这是唯一的命名入口） |
| 添加 Provider · 名称 | 是 | 部分 | 保留（这是标识，不是内容） |
| API Key · 名字 | 是 | 否 | 保留（同名可区分用途） |

**具体规则（可直接实现）：**

1. 项目名 = 仓库地址 basename 去掉 `.git`，`https://github.com/octocat/Spoon-Knife.git` → `Spoon-Knife`；`git@host:team/cache-service.git` → `cache-service`；仓库为空 → `空白工作区 · MM-DD`。用户在输入仓库地址时实时看到这个名字并可改；留空则用派生值提交。
2. 会话名 = 首条消息首行前 40 字（**已有**），不做第二个来源；用户显式改名后永不再自动覆盖（现在 `autoTitle` 只在 `Title == ""` 时写，已正确）。
3. 分支/克隆产生的会话：`branch of X` 这种英文标题改为 `X · 分支`；`克隆（再试一次）` 改为 `复制一份`，标题自动继承 + `（副本）`（现在确实这么做了，只是菜单文案是黑话）。
4. 派生失败（两个项目同名）不弹窗，追加 `-2`。

**代价.** S（前端 0.5 天 + 项目重命名入口 0.5 天）。不需要新接口：`PATCH /v1/projects` 已支持 `name`。

### 2.2 "侧边栏应该切会话，不是切项目"——是，而且这不是偏好问题：现在它把主功能挤出了首屏

**判断：完全同意。证据不是审美，是坐标——「会话」组在 y=1301，视口 900。**

现在侧边栏承担了四件事：折叠、命令面板、项目切换、项目列表。前三件都该在，第四件是错的：项目是"容器"，会话是"工作"。而且它连"切换项目"都没做好——顶部那行 `qa14-core-… / 沙箱 · 就绪 ⌄`（在项目页）或 `PiForge / 所有项目 ⌄`（在首页）带一个上下箭头，看起来是切换菜单，点下去只是回到 `/`：在首页实测 URL 不变、界面无反应（`57-project-switcher-result.png`），在项目页则是"退出项目"而不是"换一个项目"。它不给你选择。

**侧边栏应该装什么（从上到下）：**

1. **顶部 48px**：当前项目名 + 一个真正的切换菜单（最近 6 个项目 + "所有项目"入口）。菜单里每个项目一行，带"运行中"计数。
2. **搜索框**（常驻，不是 hover）：`搜索会话…`，接 `GET /v1/sessions?q=`（已有）。这是侧边栏最重要的一个控件。
3. **跨项目会话列表**，按状态分组：
   - `运行中`（带秒级计时）——最多 3 条，始终在顶部；
   - `需要你`（失败、等你确认）——红色文字徽章；
   - `今天` / `更早`——标题 + 项目名小字 + 相对时间，最多两行；
   - 保留现有的分支缩进（父子关系是真实信息）。
4. **底部**：设置 / 通知 / 账号（现有）。

**项目的家**：首页（已有 35 张卡片，补一个搜索/筛选即可）+ 顶部切换菜单。项目页仍有它自己的会话列表（那是"这个仓库的历史"，合理）。

**实现上要注意的两点**：① 列表数据用 `GET /v1/sessions`（无 project 参数，已验证返回全部 43 条），不要 35 个项目各发一次请求；② 分组依赖 `status` 字段，它已经是 `running/active/idle/failed/archived`，不需要新接口，只需要轮询/失效策略（30 秒或 SSE settle 时刷新）。

**代价.** M（2–3 天）。注意：另一个 agent 正在改这块，本节的改动应该合并进他正在做的结构，而不是并行重写。

### 2.3 "每条回复都重复 PiForge 和模型名"——是，而且真正的问题不是重复，是"一次运行被拆成七条消息"

**判断：同意，但只删标签治不了根。** 根因是渲染单位错了：Pi 的一次运行会产生多个 assistant entry（每轮工具调用一段），`MessageItem` 给每一段都渲染了独立的 header（`<span>PiForge</span>` + `<span>{turn.model}</span>`），所以一次问答变成 7 个作者、8 个时间戳（`34-run-settled.png`）。

**转录区应该长这样（同一次运行）：**

```
你                                          19:59
  先运行 ls 看看目录，再用一句话说明这个仓库是做什么的

▸ 思考 · 3 步 · 1 个工具调用失败                      ← 一行，折叠，悬停展开
  bash ls · 11ms ✓    bash cat · 5ms ✓    bash cat:hi · 12ms ✕

  这个仓库是……（最终答案，正常字重，和过程有明确区分）
```

规则（每条都能落到一个组件上）：

1. **一次 run = 一个 assistant 块**：块内不再重复作者名。作者名只在"你 / agent"切换时出现一次。
2. **模型名进 header，不进 turn**：会话 header 已经写着 `跟随默认（deepseek-v4-flash）`，够了；会话级模型变更用一条分隔线 `模型已切换为 X · 19:59`（`model_change` entry 本来就在会话树里，`54-branch-sheet.png` 能看到）。
3. **工具调用合并成一行摘要**：`3 步 · 1 个失败`，展开才是逐条命令。现在每轮工具都是一行「1 个工具调用 执行命令 11ms」+ 一段「思考」，三次运行就占了半屏。
4. **时间戳每个 run 一次**，放在 run 尾部或 hover footer；不要每个 turn 一次（同一分钟 8 次是纯噪音）。
5. **最终答案与中间叙述要有区分**：中间叙述（"notes: long.txt…"）降为次要色/更小字号，最终答案保持正常；否则用户分不清哪句是结论。
6. **失败工具在摘要行里可见**（现在有 `1 个失败`，保留），但不要整段转红。

**代价.** S（1 天；`reduce.ts` 里按 run 分组，`MessageItem` 删 header 分支，工具摘要合并）。

### 2.4 "还有更多体验上的问题"——有，按痛的顺序

1. **停止 = 报错**（§1-4）：用户的主动操作被渲染成模型故障，还建议去改密钥。这是信任问题，不是文案问题。
2. **首小时是死路**（§1-2）：新账号第一条消息必然 400，错误指向一个他看不到的 provider；`跟随默认（unknown）` 直接把内部状态打到界面上。
3. **右栏 56% + 空预览**（§1-5）：最宽的区域给了一个没打开的文件；窄屏上把对话压到 145px。
4. **首页不回答"在跑什么"**（§1-7）：35 张卡片全是沙箱状态，没有一个运行标记；通知面板明确说它不是消息中心。
5. **项目不能改名/删除**（§1-6）：唯一的删除入口在坏工作区的会话里，正常人找不到。
6. **错误面三国语言**（§1-8）：`Request was aborted`、`Scroll to end`、`Close`、`克隆（再试一次）`、原始 provider JSON。
7. **管理台不可行动**（§1-9）：16 个运行中的 agent 点不进去；只读排障要手填会话 id。
8. **术语打架**（§3）：会话 / 尝试 / run / 分支 / 克隆 / 分叉 / 旁路 / Sidecar / worktree / 工作区，同一批东西六种叫法。

## §3 命名与术语表

界面上的名词（按出现频率），以及它们实际指什么：

| 界面词 | 出现处（截图） | 实际指 | 问题 |
|---|---|---|---|
| 项目 | 全站 | git 仓库 + 沙箱 | 与"仓库"混用（卡片副标题写 `空白工作区`） |
| 会话 | 侧边栏、项目页、对话框 | 一段对话 + 一个 worktree | 与"分支""尝试""run"混用 |
| 主会话 | 项目页、对比页、header | `kind=main` 的会话 | 暗示存在"子会话"，但界面从不说"子会话" |
| 分支 | kebab、分支面板、对比页 | `kind=branch` 的会话（分叉产物） | 它是会话的一种，却像另一类对象 |
| 分叉 | 消息上的按钮、分支面板 | 动作：从某条消息开新分支 | 动词和名词（分支）没有对应关系说明 |
| 克隆 | kebab：`克隆（再试一次）` | 复制整个会话 | "克隆"是 git 词，且括号里的"再试一次"像故障恢复 |
| 旁路 / Sidecar | 按钮 `Sidecar`、面板 `这是旁路对话` | 共享工作区、只读的旁支对话 | 一个东西两个名字，其中一个还是英文 |
| 尝试 | 对比页标题 `对比 2 个尝试` | 一次被比较的方案（= 一个会话） | 只在对比页出现的第三种叫法 |
| run | composer 的 tooltip：`会中断当前 run` | 一次执行 | 英文漏到中文界面 |
| 工作区 / worktree / checkout | 对话框、卡片、坏工作区页 | 磁盘上的检出目录 | 三种写法指同一物；`worktree` 直接写在新建会话对话框的说明里 |
| 沙箱 | 首页卡片、header | 资源容器 | 用户不关心；`沙箱 · 已暂停` 占用卡片黄金位置 |
| 模型 / provider / 服务商 | 设置页、错误 toast | 模型服务配置 | 设置页叫「模型与凭据」，页内叫 Provider，错误里叫「服务商」 |
| 默认模型 / 跟随默认 / unknown | 对话框、composer、header | 未显式选择的模型 | 三种写法；`unknown` 直接露给用户 |
| 推理强度 / 思考 / thinking | 对话框、转录 | 同一件事 | 设置里叫"推理强度"，转录里叫"思考" |
| 上下文 | header meter、压缩标记 | token 用量 | 可接受，但与"上下文已压缩"的语境不同 |
| 停止 / 中断 / 打断 / 清空队列 | composer 按钮、toast | 终止当前 run | 四个词，三种语义（停止 run / 清队列 / 改口） |
| 归档 / 删除 | kebab | 隐藏 / 销毁 | 清楚，保留 |
| 采纳 | 侧栏（分支会话，本次未截到） | 把分支改动合回主干 | 术语太文，建议「合回主干」 |
| 提升为分支 | 旁路面板（代码内，本次未截到） | 把 sidecar 变成正式分支 | 可以，但"提升"在别处没有对应 |

**统一成一套（建议直接照做）：**

- **项目**（project）：一个仓库 + 一个沙箱。不再说"仓库"指代项目；卡片副标题写仓库地址。
- **会话**（session）：唯一的对话单位。分支和旁路都是会话，但表述为「分支会话」「旁路会话」。
- **运行**（run）：一次执行。禁止出现英文 `run`；"这次运行""上次运行"。
- **分支**：分叉的产物；动作叫**分叉**。菜单里 `复制一份` 代替 `克隆`。
- **旁路会话**：彻底替换 `Sidecar`（按钮、面板、toast 全改）；`旁路` 单独出现时也算不合格。
- **工作区**：替换 `worktree` / `checkout`；英文只在代码里。
- **沙箱**：只在管理员和资源相关的地方出现，会话界面不显示。
- **模型服务**：设置页的一级名词（页面标题保持「模型与凭据」）；`provider` 只留在代码与 API；错误文案统一说「模型服务」。
- **默认模型**：唯一写法。解析不出来时说「未配置」，**禁止 `unknown`、禁止 `跟随默认（…）` 里塞括号**。
- **推理强度**：唯一写法，转录里的「思考」改为「推理」。
- **停止**：唯一写法；「中断/打断/改口/清空队列」按语义拆成两个按钮：`停止`（终止 run）、`立即改口`（steer）。
- **合回主干**：替换「采纳」。
- 禁止出现在界面上的词：`尝试`、`Sidecar`、`worktree`、`克隆`、`run`、`unknown`、`Scroll to end`、`Close`、`Request was aborted`。

## §6 不做什么

1. **不要重做信息架构/换一套设计系统。** 现在的问题不是布局不好看，是五个具体决定错了（侧边栏装什么、转录渲染单位、右栏默认宽度、默认模型的可见性、错误的呈现）。换皮会把这些问题一起搬过去，还会让另一个 agent 正在做的侧边栏工作全部作废。
2. **不要做"多分支并排多窗格"（FR-3.4）。** `docs/STATUS.md` 明确记着这条是 MISSING，`workspace-panels.tsx` 的 split 是检查器的第二个面板，不是分支流。在会话页右侧已经挤爆的情况下加窗格，只会更糟。
3. **不要给转录加头像、角色动画、打字机效果。** §1-3 的结论是"少一层身份重复"，不是"再画一个身份"。
4. **不要给管理台加图表/水位盘。** 现在 16 个运行中的 agent 都点不进去；先让数字可下钻，再谈可视化。加图表是把"不可行动"包装得更精致。
5. **不要把移动端做成完整 IDE（终端 + 浏览器 + 文件编辑）。** 手机上真正要做的是"看进度、回一句话、停掉跑偏的 run"。先让对话可读（§1-5），再谈能力。
6. **不要引入"尝试/attempt"作为新概念。** 对比页的「尝试」是同一个东西的第三种叫法；应该是删掉这个词，而不是把它推广到全站。
7. **不要做项目模板 / 工作流编排 / 一键开 PR。** 后端没有对应实现（一键开 PR：FR-12.6 是 MISSING；项目模板/工作流编排：仓库里没有这个概念），而且它不解决首小时的失败。
8. **不要在模型选择器里先加成本/窗口/推理能力。** 选择器现在的问题是"哪些能用"都看不出来（`qa14-nokey`、`shared-anthropic` 缺 key 也在列表里，`55-model-picker.png`）；先修可用性标注，再谈信息量。
9. **不要给每个会话加"未读"红点体系。** 现在没有跨会话的通知来源，红点会变成第二个欺骗性的状态点（和那个 6px 的运行圆点一样）。
